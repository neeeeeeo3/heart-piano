# 自動演奏ツール

音楽イベントを記録したCSVファイルを読み込み、音符を演奏用に補正してから、PCキーボードの押下・解放イベントへ変換するAutoHotkeyスクリプトです。

このスクリプト自体は音を生成しません。変換したキー入力を、その時点で操作対象になっているブラウザやアプリへ送信します。ハートピアノと組み合わせると、CSVの内容を自動演奏できます。

## 主な機能

- CSVから音符・テンポ・サステイン情報を読み込み
- 最高音をメロディとして自動判定
- 音域をMIDIノート48〜84へ自動調整
- Romantic、Mechanical、OldTimeyの3演奏スタイル
- ルバート、レガート、スタッカート、グルーヴ補正
- 音符を物理キーボードのスキャンコードへ変換
- 高精度タイマーを使った自動演奏
- 常に手前に表示される進行状況ウィンドウ
- 演奏停止時の終了アルペジオ
- 終了時に押下状態のキーを解放するクリーンアップ

## 動作環境

- Windows
- AutoHotkey v2.0
- キー入力を受け取るブラウザまたはアプリ
- 本READMEで説明する形式のCSVファイル

このスクリプトの先頭には、次のバージョン指定があります。

```ahk
#Requires AutoHotkey v2.0
```

AutoHotkey v1では実行できません。AutoHotkey v2の導入については、[AutoHotkey v2公式インストールガイド](https://www.autohotkey.com/docs/v2/howto/Install.htm)を参照してください。

## 重要な注意事項

### キー入力はアクティブな画面へ送信されます

このスクリプトは特定のウィンドウを指定していません。演奏開始時に手前で操作しているウィンドウへ、キーボード入力が送信されます。

CSVを読み込んで`READY: F1 TO START`と表示されたら、先にハートピアノなどの演奏対象をクリックしてから`F1`を押してください。

テキストエディター、チャット、ゲームなど別の画面を選択したまま開始すると、その画面へ大量のキー入力が送られます。

### プロセス優先度がRealtimeに設定されています

初期設定では、タイミング精度を優先するため次の指定があります。

```ahk
ProcessSetPriority "Realtime"
```

Realtimeは非常に高いプロセス優先度です。PCの動作が不安定になる場合はスクリプトを終了し、必要に応じて`High`など、より低い優先度へ変更してください。

### 信頼できるスクリプトだけを実行してください

AutoHotkeyスクリプトはキーボードやマウスの自動操作が可能です。このファイルは、選択されたローカルCSVの読み込み、GUI表示、時刻計測、キー入力の送信を行います。内容を確認できない別のスクリプトへ安易に差し替えないでください。

## ファイル構成例

```text
自動演奏ツール/
├── 自動演奏ツール.ahk
├── music.csv
└── README.md
```

CSVは別のフォルダに置いても構いません。起動時のファイル選択画面から指定できます。

## 基本的な使い方

1. AutoHotkey v2をインストールします。
2. `.ahk`ファイルをダブルクリックして起動します。
3. `SELECT_CSV_FILE`画面で、演奏するCSVを選択します。
4. 画面に`READY: F1 TO START`と表示されるまで待ちます。
5. キー入力を受け取るブラウザまたはアプリをクリックします。
6. `F1`を押して演奏を開始します。
7. 途中で停止する場合は`Esc`を押します。

演奏が最後まで進むか、停止処理が完了すると、スクリプトは自動終了します。別のCSVを演奏する場合は、もう一度スクリプトを起動してください。

## 操作キー

| キー | 動作 |
| --- | --- |
| `F1` | 読み込みと変換が完了した曲を再生 |
| `Esc` | 演奏中は停止を要求。停止要求後にもう一度押すと即時終了 |

`F1`と`Esc`はグローバルホットキーです。スクリプトが動作している間は、別のアプリを操作していても反応します。

## 画面に表示される状態

| 表示 | 意味 |
| --- | --- |
| `WAITING CSV` | CSVの選択待ち |
| `LOADING...` | CSVを読み込み中 |
| `READY: F1 TO START` | 変換完了。F1で演奏可能 |
| `ULTIMA: ROMANTIC`など | 指定スタイルで演奏中 |
| `STOPPED` | Escによって停止 |
| `FINISHED` | 最後まで演奏完了 |

演奏中は、現在時間、曲全体の時間、進行状況バーが更新されます。GUIの透明度はテンポに合わせて変化します。

## 対応するCSV形式

各行には7列以上が必要です。列はカンマで区切ります。

| 列 | note_onでの意味 | Tempoでの意味 | Control_cでの意味 |
| ---: | --- | --- | --- |
| 1 | トラック名 | 任意 | 任意 |
| 2 | `note_on` | `Tempo` | `Control_c` |
| 3 | MIDIノート番号 | 1拍あたりのマイクロ秒 | 任意 |
| 4 | 現在は未使用 | 現在は未使用 | 現在は未使用 |
| 5 | ベロシティ。1以上で発音 | 任意 | コントロール番号。64でサステイン |
| 6 | 音の長さ（秒） | 任意 | 値。64以上でON、64未満でOFF |
| 7 | 開始時刻（秒） | 発生時刻（秒） | 発生時刻（秒） |

8列目以降が存在しても、現在のスクリプトでは使用されません。7列目が数値でない行は読み飛ばされるため、一般的な文字列のヘッダー行はそのまま含められます。

### CSVの例

```csv
track,type,data1,data2,data3,data4,time
Meta,Tempo,500000,0,0,0,0.000
Piano,note_on,60,0,96,0.500,0.000
Piano,note_on,64,0,90,0.500,0.000
Piano,note_on,67,0,90,0.500,0.000
Pedal,Control_c,0,0,64,127,0.000
Pedal,Control_c,0,0,64,0,1.000
```

上の例では、テンポ120 BPMに相当するテンポイベントと、ド・ミ・ソの和音、サステインペダルのON・OFFを記録しています。

## CSV読み込み時の処理

### 時刻の単位変換

CSVの6列目にある音の長さと、7列目にある開始時刻は秒として読み込み、内部ではミリ秒へ変換します。

### 最大演奏時間

初期設定の最大時間は298,000ミリ秒、つまり4分58秒です。

```ahk
MaxDurationMs: 298000
```

曲がこの時間を超える場合、すべての音符の開始時刻と長さ、およびテンポイベントの時刻を同じ比率で短縮します。曲の途中を切り捨てる方式ではなく、全体を時間内に圧縮する方式です。

### 読み込み失敗時

次の場合、エラーメッセージを表示せずにスクリプトが終了します。

- CSVを選ばずに選択画面を閉じた
- ファイルを読み込めなかった
- 有効な`note_on`イベントが1件もなかった
- 必要な列や数値が不足していた

## 演奏スタイル

初期設定は`Romantic`です。

```ahk
ActiveStyle: "Romantic"
```

`Romantic`、`Mechanical`、`OldTimey`のいずれかへ変更できます。大文字・小文字を含め、コード内の表記どおりに指定してください。

| スタイル | 主な処理 |
| --- | --- |
| `Romantic` | ヒューマナイズとルバートを有効化。音を少し強くし、長さを5%延長 |
| `Mechanical` | ヒューマナイズとルバートを無効化。ベロシティを100へ統一 |
| `OldTimey` | ルバートを無効化。ベロシティと開始時刻へランダムな揺れを追加 |

現在の出力はキーの押下と解放だけであり、ベロシティに応じた打鍵強度は送信していません。そのため、ベロシティだけを変更する処理は、ハートピアノの音量へ直接反映されません。音の開始時刻や長さに対する変更は反映されます。

## 処理パイプライン

読み込んだ音符は、優先度の小さいモジュールから順番に処理されます。

| 優先度 | モジュール | 処理内容 |
| ---: | --- | --- |
| 10 | `StyleSelectorProcessor` | 演奏スタイルに応じてフラグ、ベロシティ、長さ、時刻を変更 |
| 20 | `MelodyAnalyzerProcessor` | 同時刻に始まる音のうち、最も高い音をメロディとして判定 |
| 30 | `PassiveSkylineProcessor` | 音をオクターブ単位で移動し、MIDI 48〜84へ収める |
| 40 | `DynamicRubatoProcessor` | メロディフレーズの中間を前後へずらし、終端を長くする |
| 50 | `ArticulationLogicProcessor` | 狭い音程差をレガート、広い跳躍を短めに調整 |
| 60 | `AdvancedGrooveProcessor` | 特定の拍位置を5〜15ミリ秒遅らせる |
| 90 | `EventCompilerProcessor` | 音符を時刻順のキーダウン・キーアップイベントへ変換 |

### メロディ判定

開始時刻が同じ音の中から、最も高いMIDIノートをメロディとして扱います。

### 音域調整

MIDIノートが84より高い場合は12を引き、48より低い場合は12を足します。和音側がメロディへ近づきすぎる場合は、可能であればさらに1オクターブ下げます。

### ルバート

800ミリ秒を超える間隔をフレーズの区切りとして扱います。4音以上のメロディフレーズでは、サインカーブを使って中間音の時刻を最大約20ミリ秒前後へ動かします。最後の音は15ミリ秒遅らせ、長さを20%延長します。

### アーティキュレーション

- 連続するメロディの音程差が2半音以内で、間隔が300ミリ秒未満の場合、前の音を少し重ねます。
- 音程差が7半音以上の場合、前の音の長さを70%へ短縮します。

### グルーヴ

500ミリ秒を1周期として、周期内の200〜350ミリ秒に位置する音を5〜15ミリ秒遅らせます。

## ハートピアノと組み合わせる場合

このAutoHotkeyスクリプトのキー配置は、ハートピアノの3段構成に対応しています。

| CHIMERA内の音域 | 送信するキー段 | ハートピアノで鳴る音域 |
| --- | --- | --- |
| MIDI 48〜59 | 低音段 | MIDI 36〜47 |
| MIDI 60〜71 | 中音段 | MIDI 48〜59 |
| MIDI 72〜84 | 高音段 | MIDI 60〜72 |

現在の組み合わせでは、ハートピアノから鳴る音は、内部で処理しているMIDIノートより1オクターブ低くなります。これは両ファイルの対応表を比較した結果です。原曲と同じオクターブを保つ必要がある場合は、どちらか一方のキーマップを調整してください。

## テンポとサステインの現在の扱い

### テンポ

CSVの`Tempo`イベントはBPMへ変換され、GUIの拍動エフェクトを計算するために使用されます。キーイベントの実際の演奏時刻は、CSVの7列目にある絶対時刻を基準にしています。

### サステイン

コントロール番号64の`Control_c`イベントは`SustainEvents`へ保存されます。ただし、現在のコードでは保存後のサステインイベントを演奏イベントへ変換していません。

そのため、CSVにサステイン情報があっても、現状では物理的なサステインキーやハートピアノの音へ直接反映されません。

## タイミング制御

タイミング精度を上げるため、次のWindows機能を使用しています。

- `QueryPerformanceCounter`による高精度時刻取得
- `timeBeginPeriod(1)`によるタイマー分解能の変更
- 次イベント直前までの`Sleep`
- 1ミリ秒未満の待機時に`DllCall("Sleep", "UInt", 0)`を使用

終了時は`timeEndPeriod(1)`を呼び出し、変更したタイマー設定を戻します。また、スキャンコード1〜128へキーアップを送信し、キーが押しっぱなしになるのを防ぎます。

## よくあるトラブル

### ダブルクリックしても動かない

- AutoHotkey v2がインストールされているか確認してください。
- AutoHotkey v1へ関連付けられていないか確認してください。
- ファイルの拡張子が`.ahk`になっているか確認してください。

### CSVを選ぶとすぐ終了する

- 各行に7列以上あるか確認してください。
- 7列目が秒単位の数値になっているか確認してください。
- 2列目に`note_on`、3列目にMIDI番号、5列目に1以上のベロシティがあるか確認してください。
- 6列目の音の長さが数値になっているか確認してください。

### F1を押しても演奏されない

- `READY: F1 TO START`と表示されているか確認してください。
- 演奏対象のウィンドウを先にクリックしてください。
- 対象アプリが管理者権限で動いている場合は、権限レベルの違いによって入力を送れないことがあります。
- 別のアプリがF1を専用キーとして横取りしていないか確認してください。

### キーは送信されるが音が違う

- 対象アプリ側のキー割り当てを確認してください。
- 日本語配列と英語配列では、一部の記号キーの認識が異なる場合があります。
- ハートピアノとの組み合わせでは、現在の対応上、原曲より1オクターブ低く鳴ります。

### PCが重くなる、操作しづらくなる

`ProcessSetPriority "Realtime"`の影響が考えられます。スクリプトを終了し、`High`などへ下げて再確認してください。

### Escを押してもすぐ終了しない

演奏中に最初の`Esc`を押すと停止要求を出し、短い終了アルペジオを演奏してから終了します。即時終了したい場合は、もう一度`Esc`を押すか、タスクトレイのAutoHotkeyアイコンから終了してください。

### 音量の強弱が変わらない

現在のスクリプトはベロシティをキー入力の強さへ変換していません。送信先が通常のキーボード入力だけを受け取る場合、すべて同じ打鍵強度として扱われます。

### サステインが反映されない

サステインイベントはCSVから読み込まれますが、現在の再生処理では未使用です。対応するには、サステインのON・OFFを送信先の操作へ変換する処理を追加する必要があります。

## 実装上の制限

- 1回の起動につき、選択できるCSVは1ファイルです。
- 演奏終了後は自動でスクリプトが閉じます。
- キーの送信先ウィンドウは固定されていません。
- ベロシティは物理キーの強さへ反映されません。
- サステインイベントは読み込まれますが、再生には使われません。
- テンポイベントは主にGUIの拍動表示へ使われます。
- CSVの解析に失敗した場合、詳細なエラーダイアログは表示されません。
- GUIには通常の閉じるボタンがありません。
